# GOMO implementation plan

Goal: show live data remaining, calls remaining, and package details in WANUtility.

Design: add a native GOMO navigation page using the existing AppServices and
Changed-signal pattern. Core/GomoAccount owns validated response parsing and plain
display models; Services/GomoClient owns read-only native HTTP; GomoService owns
one refresh at a time and clears stale results. GomoPage renders native controls.

Constraints: use current WAN auto-auth, no OTP, purchases, SMS, USSD, profile-info
requests, credential persistence or response logging. Preserve existing dirty
files and LocalState. All HTTP runs off the UI thread, verifies TLS, disables
redirects/proxies/cookies, and has bounded response sizes and timeouts. Failed or
incomplete responses must never appear as zero balances. Package values retain
the carrier's units and rounding. English text falls back to Thai.

Execution: implement inline in the explicitly requested Windows checkout. The
handoff authorizes implementation and routine reversible design choices; no
additional approval gates or worktree migration. Leave changes uncommitted for
review with the user's existing work.

## Review focus

Expired session; login redirect or unrecognized subscriber; missing totals vs
real zero; navigation during an in-flight refresh; conflicting package and
aggregate rounding; hostile or malformed response content; LocalState retention.

## Verification ledger

Initial state: feat/v1 at faf9a66, pre-existing edits recorded before changes.

Results (2026-10-19, observed):

- Unit tests: `scripts\test.ps1` gives `Total tests: 59  Passed: 59` (48 existing and 11 GOMO tests).
- App build: x64 Debug, exit 0. The manifest hash equals the registered stamp, so the package was
  relaunched without re-registration. LocalState was not touched.
- Live run on the current WAN (internet profile "Mobile 18", WWAN). The log shows four requests, each `HTTP 200`
  (mobile-check, kyc/login/msisdn, profile/usage, profile/packages). The page showed data 25.48 GB of 25.49 GB,
  calls 50 mins of 50 mins, and two package cards with status, validity, allowance, speed and remaining lines.
  These match the carrier values.
- Refresh: the page shows a loading line and a spinner, and the Refresh button is disabled while a refresh runs.
  A second Invoke on the button failed with "not enabled", and the log has one request sequence per refresh.
- Navigation: leaving for Messages during a refresh, opening USSD ("No active session"), and returning showed
  the completed result. No SMS or USSD traffic was sent.
- The log contains no token text: `grep -c "authorization|rocketToken"` gives 0.
- Screenshots were taken of the app window only (`PrintWindow`).

Rulings:

- `HtmlUtilities::ConvertToText` ends the test host with a fail-fast (0xC0000409). It is replaced with a
  small tag-stripping and entity-decoding function. Observed carrier markup is only `b`, `big`, `br`, `font` and
  `span`.
- A non-null `myAISBlocked` object means the account is blocked, as in the APK (`MsisdnResponse.blocked`, which
  shows a dialog and exits). This is the new `GomoFailure::Blocked`. Login `statusId` 4 is not treated as blocked.
- Requests use the default route. Before them, the app checks that the internet connection profile is WWAN
  (`GomoFailure::NotCellular`), as the APK checks for cellular transport. WinHTTP cannot bind to an adapter.
  A Wi-Fi or VPN default route therefore gives a clear error and does not send the identity request.
- `WANUtility.vcxproj.filters` (Solution Explorer grouping only) was not edited, because it was already dirty.
- Final review fixes (each test was RED, then GREEN): `NullOptionalPackageFieldsAreLeftEmpty` and
  `DatesOutsideTheLocalTimeRangeAreShownAsSent`. Date formatting moved to `core::FormatGomoDate`.

Not verified and deferred:

- The failure UI was not seen live (expired session, not recognized, not cellular, network down). Testing it needs
  a connection change, for example turning the radio off or using Wi-Fi as the default route. Failure
  classification is covered by the parser tests only.
- Minor review items were not fixed: any non-null `myAISBlocked` value counts as blocked, including `false`; a
  401 on login says "session expired"; there is no overall deadline across the four requests (each step has a
  15 s timeout); "Last updated" stays visible after a failed refresh; the page handler captures a raw `this`
  (the same pattern as UssdPage); `Plain` leaves entities above U+FFFF undecoded.

Follow-up (2026-10-19): GOMO is enabled only on an AIS cellular connection.

- `GomoService::Available()` requires two things. First, `ModemStatus::wwanInternet` must be true: Windows'
  internet connection profile is WWAN. Second, `core::IsAisCarrier(carrier)` must be true: the first word of the
  registered provider name is "AIS", ignoring case (observed: `AIS`; dtac reports `dtac.Better Together`).
- When either check fails, the GOMO navigation item is disabled and the page shows an "not available" InfoBar.
  The page also hides any earlier values, disables Refresh, and sends no requests. `Refresh()` itself returns
  without sending anything when the feature is not available.
- Observed: unit tests 60/60 passed; the log shows `carrier='AIS' wwanInternet=1`; the GOMO item is enabled;
  the live fetch rendered.
- Not observed: the disabled state, which needs Wi-Fi or a VPN as the internet route, or a non-AIS SIM. The
  carrier-name rule is covered by `OnlyAisCarrierNamesEnableGomo`.
